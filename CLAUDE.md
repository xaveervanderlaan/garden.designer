This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project documents — read these first

The spec and plan are **private**: `docs/` is a separate git repo (remote `garden.designer-docs`, private on GitHub) that this public repo ignores. Never copy them into the public repo or quote them in public commit messages. Commit doc changes in the docs repo itself (`git -C docs add … && git -C docs commit … && git -C docs push`).

- **docs/SPEC.md** — what we're building (requirements, decisions, decision log). Items marked *(proposed)* are not yet confirmed by the user.
- **docs/PLAN.md** — how and in what order: milestones M0–M18 with checklists, architecture decisions (§2.3) and "as built" notes (§2.1). Follow §2.3 when implementing new milestones.

Workflow agreed with the user: work through PLAN.md milestone by milestone. At the end of a milestone, commit directly on `main` and push (CI deploys); tick the PLAN.md checkboxes and commit and push the docs repo; then **stop for the user to try the app** before starting the next milestone. If a decision changes, update SPEC.md/PLAN.md too.

Node 24 comes from nvm, which non-interactive shells don't load: prefix commands with `. ~/.nvm/nvm.sh &&`.

```bash

npm run lint         # oxlint --deny-warnings && prettier --check .

npx vitest run -t "switches to Dutch"       # tests matching a name
npx playwright test tests/e2e/smoke.spec.ts -g "Dutch browser"
```

- `E2E_ALL_BROWSERS=1` adds the Firefox and WebKit projects; they need system libs (gtk3/gtk4, gstreamer, …) not installed here, so they are untested.
- Playwright runs against the **production build**: its `webServer` runs `npm run build && npm run preview` on port 4173 under `/garden.designer/` (reuses a running server locally). Set `E2E_PORT` to use another port, e.g. when several git worktrees run e2e tests at the same time (a reused server on the same port would serve another checkout's build).
- This machine is Arch Linux on WSL; Playwright's `install-deps` doesn't support it. The Chromium system packages are listed in README.md (pacman).
- Definition of done for a milestone: lint, typecheck, test, build and e2e all pass; every UI string exists in EN and NL; no console errors (e2e tests collect them).
- Add dependencies with a supply-chain cool-down: `npm install --before=<date at least 2 weeks ago> <pkg>`.

## Architecture (current state)

- **Stack:** Vite 8, React 19, TypeScript 7 (native compiler: `tsc -b`, strict + `noUncheckedIndexedAccess`), Vitest 5, Playwright, i18next. Plain CSS Modules; design tokens are CSS custom properties in `src/styles/global.css`.
- **Routing** (`src/routing.ts`): a tiny hash router, chosen so GitHub Pages needs no 404 fallback. `useRoute()` subscribes to `hashchange` via `useSyncExternalStore`; `parseHash` maps `#/` → project list and `#/p/<id>` → editor (anything else → not found); build links with `hrefFor(...)`, never by hand. `App.tsx` switches on the route.
- **i18n** (`src/i18n/`): initialised by a side-effect import in `main.tsx`. Detection order is a saved choice in localStorage (`garden-designer.language`), then the browser language; `nl-*` maps to `nl`. On language change it updates `<html lang>` and `document.title`. Keys are type-checked against `locales/en.json` (`i18next.d.ts`). `locales.test.ts` enforces identical keys and `{{placeholders}}` in `en.json` and `nl.json`. Language names are endonyms in both files.
- **No hard-coded UI text:** the local oxlint plugin `scripts/oxlint-plugin-i18n.js` (rule `garden-i18n/no-literal-jsx-text`) flags letters in JSX text, static strings in JSX children, and user-facing attributes (`title`, `alt`, `placeholder`, `aria-label`, …). It is off for tests. Don't switch back to `eslint-plugin-i18next`: under oxlint it silently does nothing.
- **Data model** (`src/model/`): the zod schemas in `schema.ts` are the single source of truth; TS types are inferred from them. Changing stored data shape means bumping `SCHEMA_VERSION` and adding a step to `MIGRATIONS` in `migrations.ts` (`MIGRATIONS[n]` upgrades n → n+1). Units are metres; timestamps are epoch ms. Version 2 (M4) gave the background (site plan) its pixel size and calibration; its visibility/lock is the "background" layer. Version 3 (M5): plant colours come from a fixed palette (`PLANT_COLORS`, with flower/foliage/autumn subsets; hex values in `styles/plantColors.ts`) and `flowerColors` is a list (the first one is drawn). Version 4 (M6): `settings.overlapThreshold` (fraction of the smaller plant's diameter, default 0.2). Version 5 (M8): every object has `status: 'existing' | 'new'` (`MIGRATIONS[4]`: existing for objects on the existing layer, else new; `plantingSchema.status` is optional); status decides the layer (existing → "existing"), see Objects. Version 6 (M9): `GardenObject` gets optional `variant` (symbol size/look) and `plantId` (hedge species); `MIGRATIONS[5]` changes no data. Surface material is stored in `material` and defaults per kind (`materialOf`). Version 7 (M10, `MIGRATIONS[6]`): object kind `dimension` (a polyline, always on the measurements layer) and `settings.areaLabels` (default off). Version 8 (M12, `MIGRATIONS[7]`): `settings.sunThresholds` (`{ fullSunHours, partShadeHours }`, default 6/3 h; zod requires 0 ≤ part < full ≤ 24). Version 9 (M15, `MIGRATIONS[8]` changes no data): optional `rowAngleDeg` on objects (row direction of vegetable/raised beds, map-style [0, 180); absent = `defaultRowAngle`, so it follows corner edits). Version 10 (M19, `MIGRATIONS[9]` changes no data): optional `project.brief` (design brief: styles, must-haves, screened plot edges, plant wishes, count, design area, `mayChange` ids).
- **Persistence** (`src/persistence/`): Dexie/IndexedDB with tables `projects` and `assets` (binary files as `ArrayBuffer`, kept out of the project record). Always read projects through `loadProject()`, which migrates and validates. `.garden.json` export/import lives in `gardenFile.ts`: an import always creates a new project (new project and asset ids), and failures surface as `ImportError` codes that map to i18n messages. The project list reads via `useLiveQuery`, so it updates by itself after writes. Assets no longer referenced (a replaced or removed site plan) are kept while the design is open, so undo can bring them back; `pruneUnusedAssets` deletes them when a design is opened, and exports only include assets in use (`assetIdsInUse`).
- **Plant library:**
  - **Built-in plants** are JSON in `src/data/plants/<batch>.json`, merged by `index.ts` (`BUILT_IN_PLANTS`, `builtInPlant(id)`). The JSON is the source of truth, validated by `plants.test.ts` (schema, ranges, consistency), not at runtime. Ids are slugs of the Latin name, plus a suffix for a variant (`acer-campestre-hedge`). `verified: false` shows an "Unverified" badge; after the user spot-checks the tables from `npm run plants:review`, apply their corrections and set `verified: true`.
  - **Custom plants** are in `project.customPlants` with ids `custom-<uuid>`. `findPlant` looks there first, then in the built-ins; always display names through `plantName` (falls back to the other language, then Latin). Ops are in `model/plants.ts`; deleting a custom plant also removes its plantings (one undo step). `soilSuitability` is the soil rule for both the detail card and (M6) the warnings.
  - **UI** (`src/features/library/`): `LibraryPanel` (search, category tabs, filters; list ↔ `PlantDetail`), `PlantFormDialog` (custom plants), commands in `actions.ts`. Library view state is in `libraryStore`, not in `uiStore`. Search/filter logic is pure (`search.ts`: accent-insensitive, every word must occur in a NL/EN/Latin name); the form's draft ↔ plant conversion is in `plantForm.ts`.
  - **Symbols:** `styles/plantSymbols.ts` gives each category a symbol as SVG paths in a unit circle (radius = half the spread). The library draws them as SVG; the plan draws them as `Path2D` in Konva `sceneFunc`s (see Canvas). Months display through `i18n/months.ts` (`formatMonths` → "Jun–Aug"; runs continue over the turn of the year).
- **Beds & plantings** (M6):
  - **Beds** (`model/beds.ts`) are `GardenObject`s of kind `bed-ornamental` (layer "plants") or `bed-vegetable` (layer "vegetables") with a polygon shape. A planting's `bedId` is derived from geometry: `relinkBeds` links each planting to the topmost bed containing it, and every op that moves plants or changes beds calls it (`moveItems`, `transformObjects`, `pasteItems`, `deleteItems`, bed corner ops, `addPlantings`). Moving a bed takes its plants along (`withPlantsInBeds`); deleting a bed keeps its plants.
  - **Plantings** (`model/plantings.ts`): `addPlantings` (one undo step), `swapSpecies`, `speciesCodes` (1, 2, … in order of first appearance: language-independent label codes, also used by the planting list), `fillBedPositions` (staggered pattern from `geometry/planting.ts` minus spots overlapping existing plants; refuses > `MAX_FILL_PLANTS`), `defaultRowSpacingM` (hedge 0.33 m, crops their in-row spacing, else the spread). `plantingList.ts` counts per species, total or per bed.
  - **Warnings** (`model/warnings.ts`) are computed, never stored: `plantingWarnings(project, { view, radiusM })` gives overlap (sweep along x; hedging plants may overlap each other), outside-plot and soil (`soilSuitability`) warnings; `designWarnings(project, view)` caches per project version and growth view. Overlaps are checked at the size in the viewed growth year (default `'mature'`), between plantings already in the ground then; the plan, warnings list and properties all pass the view bar's year. Severity: soil `dry` is a `notice` (amber ring), the rest `warning` (red badge). Sun (M12): `designWarnings(project, view, sunMap)` takes the latest computed map (cached per map identity); a planting's level is `dominantSunLevel` under its canopy, classified with the design's thresholds. Two steps from every accepted level is a `warning`, one step a `notice`. No sun warning without a map, for existing or unplanted plantings, unknown plants, or plants that cast shade themselves (trees, shrubs, hedging, fruit ≥ 0.5 m: the map includes their own shade). Structures (`overlap-object`): a planting in the ground in the viewed year whose canopy reaches into an object of `STRUCTURE_OVERLAP_KINDS` (buildings, terrace/path/driveway, wall/fence/gate) gets a `warning` when `structureOverlapFraction` (depth over the plant's diameter) exceeds `overlapThreshold`. Climbers are exempt, existing–existing pairs skipped, objects outside the plot count; grouped per species and object kind, listed under the plant only. E2E: `structureOverlap.spec.ts`.
  - **Rows** (M15, `model/vegRows.ts`): `isRowBed` (vegetable and raised beds), `bedRowAngle`/`setBedRowAngle`, `bedFill(project, fill)` is what "Fill bed" lays out. For a row bed and a plant with `veg` data it gives rows (`layoutRows` with the crop's row and in-row spacing, editable in the fill panel, plus an optional number of rows); each fill packs its rows after the existing ones (`occupiedAcrossM`), from the top for horizontal rows and from the left for vertical ones. Anything else keeps the staggered fill. Crops in the same row bed give no overlap warnings. Row direction (Properties, `RowDirection`: degrees and "Turn 90°", plus the calendar button) also sets the bed's row-line pattern; it turns with the bed.
  - **Look:** `styles/plantAppearance.ts` is the one place that sizes and colours a plant: `plantAppearance(plant, view, plantedYear)` with a `PlantView` `{ year, month }` (M13/M14, see View bar). Results are cached, so equal inputs give the same object. Season states map to colours there: flowering/leaf/autumn recolour the whole symbol; `bare` keeps only outlines (twig brown, `SEASON_COLORS`) plus the trunk; `dormant` is faint greys; a planting not in the ground yet in the viewed year is a `ghost` (see-through at its planting size, dashed ring, still selectable; `plantDrawing.ts` draws it). `styles/elementStyles.ts` has bed fills/outlines, the vegetable bed's row `pattern` and `PLANTING_MARKS` (selection, warning/notice colours, label font).
- **Design state** (`src/store/projectStore.ts`): a zustand store holding the open project plus its undo history (`past`/`future`). Every edit goes through `update(change, { history?, coalesce? })`. It bumps `updatedAt`, records an undo step, and autosaves after `AUTOSAVE_DELAY_MS` (debounced).
  - Updates sharing a `coalesce` key within 1 s merge into one undo step: text fields, nudges.
  - `history: false` keeps view-ish changes (layer show/lock) out of undo, and undo keeps the current layer state.
  - Commit continuous gestures (drags, transforms) once, on release.
  - `open`/`close` flush pending saves and use a generation counter, so overlapping calls (React StrictMode's double effects) can't clobber each other.
- **Editor** (`src/features/editor/`):
  - **View state** (viewport, selection, tool, cursor, help, label mode, stamp/fill state, dialogs) is in `src/store/uiStore.ts` and never in the project store. Tools: `select`, `pan`, `draw` (with a `DrawTarget`: plot, bed or row), `calibrate`, `stamp`, `fill`; starting one clears the others' state.
  - **Commands** (`actions.ts` → `editorActions`) are shared by the toolbar, panels and shortcuts. They read stores via `getState()` and prune the selection to editable items after undo/delete/locking.
  - **Shortcuts:** `shortcuts.ts` `SHORTCUTS` is the single source for key handling and the help dialog. Shortcuts are ignored while typing in form fields. Add-menu shortcuts: `S` structures, `T` surfaces, `F` boundaries, `W` water & extras (they open `uiStore.objectMenuOpen`).
  - **Canvas:** the Konva canvas (`canvas/GardenCanvas.tsx`) is lazy-loaded. Its world group is transformed by the viewport (`screen = world × scale + offset`; metres in, pixels out).
    - Each item is a group at (0, 0). A drag or Transformer rotate/resize is baked into the item's coordinates on release via the pure ops in `src/model/edit.ts`, then the group is reset.
    - Copy Konva's `getTransform().getMatrix()` before resetting a node: it is reused and mutated in place.
    - Use `strokeScaleEnabled={false}` for pixel-width strokes.
    - Closed shapes that should only be clickable on their line need `fillEnabled={false}`: Konva hits the inside of a closed line even without a fill.
    - Draggable handles must have stable keys and props that don't change during their own drag (render them from committed data, show drafts elsewhere). A key change remounts the node and silently ends the drag.
    - Screen-space overlays (labels, handles, drawing preview) live in a separate layer and convert with `worldToScreen`.
    - Beds and plants are custom Konva `Shape`s whose `sceneFunc` draws with the native context (`canvas/plantDrawing.ts`) and reads the zoom at draw time (`getAbsoluteScale`), so pixel-sized things (outlines, labels, badges, less detail below 7 px radius) never need a React re-render on zoom; `Items` stays memoised. `hitFunc` draws a simple circle/polygon. Labels and warning badges of all plants are one shape on top (`PlantMarks`), following dragged groups via `handlers.offset`. Placement previews are one see-through shape (`PlantPreview`).
    - `ShadowLayer` (M11) is its own `listening={false}` layer between the items and the overlays: one see-through `Path` (`SHADOW_STYLE`) of `designShadow(project, year, sun)` (`view/sunView.ts`: all casters whatever their layer, plants at the view bar's year, unplanted ones cast nothing), from committed data, only while the sun is on and up and the "shadows" layer is visible. `NorthArrow` is an HTML/SVG overlay in the plan area's top-right corner, `role="slider"` (0–359): drag (Shift snaps to 15°) commits once on release; arrows ±1°, Shift ±15°, coalesced into one undo step (`setNorthAngle`).
    - Beds get corner handles like the plot (`CornerOverlay`, formerly `BedOverlay`; `OutlineOverlay` is shared with `PlotOverlay`) instead of the Transformer. The raised bed counts as a bed (`BED_KINDS`).
    - Dropping a plant from the library is HTML drag and drop (`library/drag.ts`, `PLANT_DRAG_TYPE`): the drop target can't read the data during `dragover`, so the dragged id is also in `libraryStore.dragging`.
  - **View bar** (`view/`, above the plan, M13/M14): a year slider (`growthStops`: planting year … +10, fully grown; default fully grown), a month select with previous/next buttons (default "No month" = the usual colours) and the bloom chart button; at the right the sun controls (M11, `SunControls`): on/off, date, quick picks 21 Mar/Jun/Sep/Dec, a time slider from sunrise to sunset (5 min steps), play/pause and an altitude/azimuth readout. Sun state is `uiStore.sun` (`{ date, minutes }` or null = off; turning it on picks today/now or solar noon and shows the "shadows" layer) and `sunPlaying` (a chained `setTimeout` loop, +10 min per 100 ms, stops at sunset); the maths is in `view/sunView.ts` (`sunRange`, `defaultSunMoment`, `clampMoment`, `quickPick`, `playStep`, `useSunPosition`). State: `uiStore.growthStop`, `month`, `bloomChartOpen` (not undone, not saved, reset when a design opens). `view/plantView.ts` turns it into a `PlantView`: `usePlantView(project)` (stable object), `currentPlantView(project)` outside React, `growthViewOf` (stops count from `growthReferenceYear`, the earliest planting year). Anything else sized by the year uses the same view, e.g. tree shadows (`designShadow`). `VegCalendarDialog` (M15, view bar button and the row direction control of vegetable/raised beds; `uiStore.vegCalendar = { bedId } | null`): months as rows × sow indoors / sow outdoors / plant out / harvest (crop names from `vegCalendar`), current month marked, quiet months one "Nothing to do" cell, month button shows that month on the plan; the bed select lists beds with crops. `VegCalendarTable` is presentational. `BloomChartDialog`: a 12-column table (`bloomChart`), whole design or one bed, a summary row of colour bands, hatched empty months with a hint; a month's column header shows that month on the plan.
  - **Side panels:** right: Properties, Warnings and Planting list (`CollapsibleSection`), Layers. The design settings dialog (toolbar gear, `SettingsDialog`) saves name, soil, grid size, overlap threshold and (M11) latitude/longitude (manual) and north angle as one undo step. Toolbar: one row that never wraps as a whole (the name field shrinks, then the tool groups wrap inside their box), so the plan's position doesn't jump when the save status changes length. M10 added Areas and Legend sections (`AreasPanel`, `LegendPanel`, collapsed, between Planting list and Layers) and the area-labels checkbox in `LayersPanel` (`settings.areaLabels`, not undoable).
  - **Plot:** the plot is selectable as `PLOT_ID` and belongs to the "existing" layer. Its operations are in `src/model/plot.ts`; corners are labelled A, B, C, …
  - **Objects** (M8: houses, structures, terraces, paths, fences, …): presets per kind in `model/objectKinds.ts` (`OBJECT_PRESETS`: shape type, default height/thickness, optional `sizeM`); ops in `model/objects.ts` (`addObject`, `shapeForKind`, `defaultFootprint`, `setObjectStatus`, `setObjectKind`, `resizeObject`/`rotateObjectTo` along the object's own frame, corner/edge ops). Draw order is `model/drawOrder.ts` (bands per kind; trees/tall fruit are canopies; `reorderItems` stays within a band and returns the same project when nothing moves); Home/End/PgUp/PgDn reorder (to front/back, forward/back; ignored in form fields). `geometry/frame.ts` holds the object's frame maths (`shapeFrameDeg`, `frameBox`, `rectangleFromCorners`, `rectangleAround`). Canvas: `canvas/ObjectShapes.tsx` + `objectDrawing.ts` draw outlines, lines and point symbols; custom outline shapes must override `getSelfRect` with their points' bounding box or the Transformer collapses to (0, 0). Panels: `panels/ObjectProperties.tsx` (beds go through it too; `BedProperties` adds bed specifics), `objects/ObjectMenu.tsx` (toolbar "Add a structure" menu). Objects outside the plot give no warnings. M9: `OBJECT_PALETTE` has four groups (structures, surfaces, boundaries, extras) with one toolbar menu each (`ObjectMenu group`, `uiStore.objectMenuOpen: PaletteGroup | null`). Surface kinds have `MATERIALS_BY_KIND` (`setObjectMaterial`; styles in `MATERIAL_STYLES`, `objectStyle(object)`); symbol kinds (furniture, lighting, play, compost, rain barrel, …) have `SYMBOL_VARIANTS` with real sizes (`symbolFor`, `symbolRadiusM` replaces `POINT_OBJECT_RADIUS_M`; `geometry/bounds.ts` `objectBounds` sizes points by it). Hedges link to a hedging species (`setHedgePlant`, `hedgePlantCount`; deleting that custom plant unlinks it). Net area (`model/netArea.ts` `surfaceAreas` → gross/net, via `geometry/clip.ts` `differenceArea`): net = gross minus surfaces/beds/buildings drawn on top (draw order); lines and symbols don't count; Properties shows both for surfaces.

Pixels map to metres as `offset + R(rotationDeg)·(pixel × metresPerPixel)`; stored rotations are clockwise on screen (like Konva), the panel shows them map-style (anticlockwise positive). It's drawn by `canvas/SitePlan.tsx` in its own Konva layer (dragged and rotated with a Transformer, never resized).

While the viewport is still the fitted one, `GardenCanvas` re-fits when the plan area changes size (a panel below it opening/closing, a window resize), measuring the container in a layout effect. Number display and parsing go through `src/i18n/units.ts` (decimal comma in NL, NBSP before units). - **Time & print logic** (pure and unit-tested, for M13–M16; the UI calls it, nothing is stored; growth and season are wired up via the View bar):
  - **Growth** (`model/growth.ts`): `plantSizeAt(plant, plantedYear, view)`, where `view` is a year or `'mature'`. A plant starts at its category's planting size (`PLANTING_SIZE_BY_CATEGORY`; fruit trees, ≥ 3 m, get their own) and is never more than half its mature size at planting. It grows linearly to its mature size over `yearsToMature`; with `yearsToMature` ≤ 1 it is mature from the planting year. Before the planting year it has its planting size: check `isPlanted` to hide or ghost it. Slider stops come from `growthStops(growthReferenceYear(...))`.
  - **Season** (`model/season.ts`): `plantAppearance(plant, month)` returns `{ state, color }`; map `color` with `PLANT_COLOR_HEX`. The rule follows from `seasonalHabit`:
    - In bloom, the first flower colour always wins.
    - Autumn colour shows in Oct–Nov, for evergreens too.
    - Deciduous woody plants are `bare` (outlined) Dec–Mar. Herbaceous plants are `dormant` then, and deciduous grasses stay in their autumn colour until March.
    - Bulbs are in leaf from one month before they bloom to one month after. Annual vegetables and herbs show only while they are in the ground (`inGroundMonths`).
  - **Summaries** (`model/bloomChart.ts` → `bloomChart`, `model/vegCalendar.ts` → `vegCalendar`): per month, for the whole design or one `bedId`. Names come from `plantName`, plantings of unknown plants are skipped, and the sort order is stable.
  - **Rows** (`geometry/rows.ts`): `layoutRows(outline, { angleDeg, rowSpacingM, inRowSpacingM })` gives row pieces with plant positions. Each plant's row × in-row rectangle stays inside the bed (which may be concave), and a row splits where it crosses a notch. `defaultRowAngle` runs the rows along the longest edge.
  - **Print scale** (`export/scale.ts`): A4/A3 page layout (10 mm margin, 15 mm title block at the bottom) and `planAreaM`. `fitsAtScale` drives the warning; `bestScale` picks from 1:50/100/200 and `bestOrientation` suggests the orientation. `printedWorldBounds` is the world area the page shows, `planImageSizePx` and `pxPerMetre` are at 300 dpi, and `scaleBar` gives a 1/2/5 × 10ⁿ m length.
- **Sun & shade core** (M11/M12, pure; M11's UI is in the View bar and Canvas, the sun-hours map and worker UI are M12):
  - **`geometry/sun.ts`** wraps suncalc **v2**: degrees, azimuth = compass bearing clockwise from north, apparent altitude (v1 used radians from south). Dates are `LocalDate` + minutes after local midnight in Europe/Amsterdam; `localInstant` handles DST via `Intl`, independent of the machine's zone. `northAngleDeg` = clockwise angle on screen from "up" to north, so bearing b lies along `(sin(north+b), −cos(north+b))` on the plan. `shadowStep(sun, north)` is the plan offset per metre of height (length 1/tan(altitude), altitude clamped to ≥ 1°), or null when the sun is down.
  - **`geometry/shadows.ts`**: casters are `prism` (a `MultiPolygon` footprint from `baseM` to `heightM`) or `canopy` (a disc from `baseM` to `topM`; trees start at ⅓ of their height). Polygons use polygon-clipping's `[x, y]` format with open rings. `shadowPieces` (no clipping, used per sample) → `mergePieces`/`shadowAt` (union for drawing; `toSvgPath` for a Konva `Path`). Polylines are buffered with round ends and joins, like the canvas draws them. No sun → no shadows.
  - **`geometry/projectCasters.ts`** turns a `Project` into casters (objects with `heightM`; trees, shrubs, hedging and fruit ≥ 0.5 m; pergolas/carports as roofs; `plantSize` option for growth). It's a separate file so the worker doesn't bundle the plant library.
  - **`geometry/sunHours.ts`**: a grid (0.5 m cells, row-major, `gridForBounds` caps the cell count), 15-min samples from sunrise to sunset, shadow pieces scan-converted per sample. `sunHoursJob` is a generator (one sample per step); `computeSunHours` (sync) and `computeSunHoursAsync` (time-sliced) take `onProgress` and an `AbortSignal`. Classification (`classifySunHours`, default 6 h / 3 h) maps to the `SUN_LEVELS` ids; `dominantSunLevel` + `sunMismatch` drive the plant warning.
  - **Worker** (`src/workers/`): `sunHoursClient.ts` (`createSunHoursClient().compute(input, { onProgress, signal })`) talks to `sunHours.worker.ts` using the messages in `sunHoursProtocol.ts`. The message logic is the plain `createSunHoursHandler` (unit-tested without a Worker), and the result's `hours` buffer is transferred. Build the casters on the main thread and pass them in.
  - **Sun-hours map UI** (M12, `features/editor/sunmap/`): `sunMap.ts` (pure: `sunMapInput` = grid over the plot's bounding box masked to the plot, casters at the view bar's year via `growthPlantSize`; `sunMapKey`, `sunMapPixels`, `levelShares`), `sunMapActions.ts` (`computeSunMap`/`cancelSunMap`/`clearSunMap`/`setSunMapVisible`; one lazy worker client; `setSunHoursClientForTests`), state in `store/sunMapStore.ts` (status, progress, result, key, visible; `uiStore.reset()` calls `resetSunMap()`, which aborts a running job). The map is view state: not saved, not undone, and never recomputed automatically; when `sunMapKey` of the current input differs from the result's, `SunMapPanel` (collapsed side section) shows "out of date" + Recompute. Threshold changes only reclassify. `canvas/SunMapLayer.tsx` draws the classes as one Konva `Image` (1 px per cell, no smoothing, `SUN_MAP_STYLE`) in a `listening={false}` layer just below `ShadowLayer`.
- **Design proposals (M19)** (`src/proposals/`, UI in `features/editor/proposals/`): copy-and-paste with Claude, no network. The toolbar's "Design ideas…" dialog has three tabs: Brief (`BriefForm`, saved into `project.brief` via `setBrief`/`setBriefArea` in `model/brief.ts`, one undo step), Prompt (`PromptStep`; `prompt.ts` `buildPrompt` is pure and built from `promptSections`; it never includes the name, location, site plan or labels; `catalogue.ts` lists plants, `sunGrid.ts` downsamples a current sun map) and Proposals (`AnswerStep`).
  - **Answer:** `parse.ts` `parseAnswer` takes JSON from code fences or bare text, salvages the complete proposals of a truncated answer and returns per-proposal `AnswerProblem`s (codes map to i18n); `mergeProposals` merges by id; `buildContinuePrompt` asks for the missing ones. `format.ts` holds the zod schemas (strict on kinds, geometry, materials, variants; unknown keys stripped) and the JSON Schema given to Claude; `garden-proposals/1` is the versioned format. `E1…`/`P1…` short refs (`baseRefs`) stand in for ids.
  - **Expansion:** `expand.ts` `expandProposal(base, proposal, { year })` is pure and deterministic and uses the model ops (`addObject`, `addPlantings`, `fillBedPositions`, `bedFill`, …). It clips to plot ∩ `brief.area`, drops overlapping plants, and `plantMatch.ts` fuzzy-matches unknown plant ids on the Latin name (else drops and reports). Pass the saved project: it reads `base.brief`. Only items ticked in `mayChange` can be removed.
  - **Storage:** Dexie `version(2)` table `proposalSets` (`persistence/proposalSets.ts`: last 5 sets per design, deleted with the design, not exported). `applyProposal.ts` flushes the store, then `duplicateProject(id, name, change)` applies the expansion inside the transaction and validates with `projectSchema` (atomic), and navigates to the new design.
  - **Gallery (M20):** the Proposals tab lists cards (`ProposalGallery`, `ProposalCard`; sort/filter by figure, "Starred only", selection with Use/Regenerate/Discard selected). `starred` ids live on the `ProposalSet` (`toggleStar`, `discardProposals(set, ids, now)`). Pure helpers in `src/proposals/`: `figures.ts` (`ProposalFigures`, `compareByFigure`), `checklist.ts` (brief must-haves/screening met/partly/missing; only rendered when the brief has some), `fingerprint.ts`, `followUp.ts` (`buildFollowUpPrompt`: "more like this" or regenerate). Thumbnails (`thumbnails.ts`): an in-memory cache keyed by `thumbnailKey`, a queue rendering one at a time with the export renderer (`useThumbnail`), so cards fill in one by one. `ProposalPreview` is a dialog over the gallery (`ViewerPlan` with layer, year and month controls, Previous/Next, star, use, more like this); its Escape handler calls `preventDefault` and `DesignIdeasDialog` ignores defaulted Escapes. `FollowUpPanel` shows the copyable prompt above the paste box. Gotchas: jsdom component tests rendering cards must mock `useThumbnail` (no canvas); while the preview is open there are two `plan-area` test ids; in e2e use exact button names ("Next" also matches "Next month"; the plants layer is "Beds & plants"). `proposals.spec.ts` also covers the gallery (12 thumbnails, star, preview, Escape, use) and use several / more like this.
  - **Gotchas:** zod v4 issues carry no input (`required` is detected from the message); `DrawTarget` `design-area` closes the dialog while drawing and reopens it (draft saved first); shortcuts are ignored while the dialog is open; the sample answer `tests/e2e/fixtures/sample-answer.md` is hand-written and checked by `sampleAnswer.test.ts` and `proposals.spec.ts` (grant clipboard permissions; "Use this design" needs a regex name).
- **Export (M16)** (`src/export/`, UI in `features/editor/export/`): a toolbar button opens `ExportDialog` (PDF default / PNG; paper, orientation, scale with a "(suggested)" option and a `role="alert"` when `fitsAtScale` fails). `runExport` reads the stores and lazy-imports `planExport` (`exportPng`, `exportPdf`), then `downloadBlob` (`features/projects/download.ts`).
  - **Renderer:** `renderPlan.tsx` mounts `PrintStage.tsx` (an offscreen react-konva Stage, all layers `listening={false}`, reusing `Items`, plot, site plan, `SunMapLayer`, `ShadowLayer`; no selection, badges or grid) with `createRoot` on a detached div, calls `stage.toCanvas({ pixelRatio })` and unmounts. `canvas/assetImage.ts` (`loadAssetImage`) preloads the site plan. Konva's `Stage.toCanvas` ignores a Layer's `imageSmoothingEnabled`, so `SunMapLayer` turns smoothing off in the Image's own `sceneFunc`.
  - **Print sizing** (`exportOptions.ts`, pure): the stage is laid out at `PRINT_LAYOUT_DPI` (120) and rendered at `pixelRatio` = 300/120, so pixel-sized things (1 px lines, 11 px labels) print at the same size whatever the scale. `printViewport`, `designBounds` (also used by zoom-to-fit), `pdfDefaults`, `pngSize` / `MAX_EXPORT_PIXELS` (16.7 MP, bigger PNG sizes disabled), file names.
  - **PDF:** jsPDF 4.2.1 is `await import`ed in `exportPdf` only; its optional deps (html2canvas, dompurify, canvg) are aliased to `optionalDepStub.ts` in `vite.config.ts` so they aren't bundled. Page 1: plan as JPEG, frame, title block, scale bar, north arrow (layout maths in `pdfLayout.ts`: `titleBlockLayout`, `northArrowShape`, `flow`, `listLayout`). Page 2+ (portrait, `pdfLists.tsx`): legend (swatches rendered from the panel's SVG by `legendSwatches.tsx` `swatchPng`, text from `panels/legendItems.tsx`/`legendText.ts`) and the planting list of the whole design, footer "Page n of N". Text is vector Helvetica (WinAnsi): every string goes through `pdfText()`.
- **Tests:**
  - **Setup:** `src/test/setup.ts` loads `fake-indexeddb/auto` first, then resets IndexedDB, localStorage, the URL hash and the language (`en`) before each test. `src/test/fixtures.ts` has a sample project/asset/plant.
  - **Fake timers:** fake only `setTimeout`/`clearTimeout`/`Date`, never `setImmediate`: fake-indexeddb runs on it.
  - **Canvas in jsdom:** jsdom has no canvas, so component tests that render the editor `vi.mock` the `GardenCanvas` module. The canvas is covered by Playwright.
  - **Locations:** Vitest only picks up `src/**/*.test.{ts,tsx}`. E2E specs live in `tests/e2e/`; each test gets a fresh browser context, so a fresh IndexedDB.
  - **e2e fixture:** the editor e2e tests import `tests/e2e/fixtures/sample.garden.json` and compute screen positions from the zoom-to-fit maths (padding 48 px), using the `plan-area` element's box *after* any panel below the plan has opened (a fitted view re-fits then), floored like the app's `elementSize`. Its sun-hours test cancels a run (holding the worker script back via `context.route`, as the whole map takes well under a second) and times a growing-season map (< 5 s, longest frame gap < 200 ms).
- **Konva hit map:** it refreshes on the next animation frame, so a click immediately after a state change can miss. Retry with `expect.poll`.
- **Lazy routes & storage errors:** `features/shell/LazyRoute.tsx` lazy-loads the editor route. A failed write is classified by `persistence/storageErrors.ts` (`'full'` for QuotaExceededError anywhere in the error chain, else `'failed'`). The store keeps `saveError` while `saveState === 'error'`: edits stay in memory, the save is retried on the next change and in `flush()` (close/open). `StorageErrorBanner` (above the view bar) offers a backup export of the in-memory design; leaving the editor in that state asks `confirm`, and `beforeunload` warns only then. Import is one transaction (nothing half-created); the site plan dialog maps quota to `storageFull`; the list page shows `storage.full`.
- **PWA / offline** (config in `scripts/vite-pwa.ts`, app side in `src/pwa/`):
  - **Service worker:** `vite-plugin-pwa` (`generateSW`, Workbox) builds `sw.js` and `manifest.webmanifest` in `vite build` only; it is disabled in dev and Vitest. It precaches every built file whose extension is in `PRECACHE_EXTENSIONS` (JS chunks incl. lazy ones, CSS, the pdf.js worker `.mjs`, the `pdfjs/` fonts/wasm/ICC files, icons): new chunks and assets are included automatically, but a new file *type* must be added to that list. A file over `maximumFileSizeToCacheInBytes` (4 MiB) fails the build. Navigation falls back to `index.html`; no runtime caching, no external requests.
  - **Updates:** the app registers the worker itself (`registerServiceWorker` in `main.tsx`, after `load`, production only) and checks hourly. A new version waits (`registerType: 'prompt'`, `clientsClaim` but no `skipWaiting`); `UpdatePrompt` (`role="status"`, only rendered while an update waits) offers Reload, which flushes the autosave, posts `SKIP_WAITING` and reloads on `controllerchange`.
  - **Icons:** `npm run icons` renders `public/icons/*.png` (192/512, maskable, apple-touch) from the favicon's leaf with Playwright's Chromium; the manifest colours are read from the `global.css` tokens. iOS meta tags are in `index.html`.
  - **Testing:** `tests/e2e/offline.spec.ts` waits for `navigator.serviceWorker.ready` + a controller, compares the precache with the files in `dist/`, then `context.setOffline(true)`, reloads and uses the app (responses must come from the service worker). It simulates a new version by registering `sw.js?next`. Other specs run with the worker installing in the background; in a page it controls, `page.route` doesn't see the requests it answers. To try offline by hand: `npm run build && npm run preview`, open the app once, then tick *Offline* in DevTools → Application → Service workers and reload.
- **Deploy:** `.github/workflows/ci.yml` runs verify (lint/typecheck/unit/build) and e2e on every push; on `main` a deploy job publishes `dist/` to GitHub Pages (https://xaveervanderlaan.github.io/garden.designer/). Vite `base` is `/garden.designer/`, so runtime asset URLs must use `import.meta.env.BASE_URL`, not `/`.

## Constraints from the spec

- Privacy and offline: no backend, accounts, analytics or external API/CDN calls. Bundle everything locally (as with pdf.js and its assets). User data stays in the browser (IndexedDB) and moves between devices only via exported `.garden.json` files.
- 2D top-down plan only; metres everywhere in the data model; NL uses a decimal comma, so number inputs must accept both `12,5` and `12.5`.
- Formatting: Prettier with no semicolons, single quotes, width 100; Markdown files are excluded from Prettier.
