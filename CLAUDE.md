# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project documents — read these first

The spec and plan are **private**: `docs/` is a separate git repo (remote `garden.designer-docs`, private on GitHub) that this public repo ignores. Never copy them into the public repo or quote them in public commit messages. Commit doc changes in the docs repo itself (`git -C docs add … && git -C docs commit … && git -C docs push`).

- **docs/SPEC.md** — what we're building (requirements, decisions, decision log). Items marked *(proposed)* are not yet confirmed by the user.
- **docs/PLAN.md** — how and in what order: milestones M0–M18 with checklists, architecture decisions (§2.3) and "as built" notes (§2.1). Follow §2.3 when implementing new milestones.

Workflow agreed with the user: work through PLAN.md milestone by milestone. At the end of a milestone, commit directly on `main` and push (CI deploys); tick the PLAN.md checkboxes and commit and push the docs repo; then **stop for the user to try the app** before starting the next milestone. If a decision changes, update SPEC.md/PLAN.md too.

Set `E2E_PORT` to use another port, e.g. when several git worktrees run e2e tests at the same time (a reused server on the same port would serve another checkout's build).

- Definition of done for a milestone: lint, typecheck, test, build and e2e all pass; every UI string exists in EN and NL; no console errors (e2e tests collect them).
- Add dependencies with a supply-chain cool-down: `npm install --before=<date at least 2 weeks ago> <pkg>`.

## Architecture (current state)

- **Stack:** Vite 8, React 19, TypeScript 7 (native compiler: `tsc -b`, strict + `noUncheckedIndexedAccess`), Vitest 5, Playwright, i18next. Plain CSS Modules; design tokens are CSS custom properties in `src/styles/global.css`.
- **Routing** (`src/routing.ts`): a tiny hash router, chosen so GitHub Pages needs no 404 fallback. `useRoute()` subscribes to `hashchange` via `useSyncExternalStore`; `parseHash` maps `#/` → project list and `#/p/<id>` → editor (anything else → not found); build links with `hrefFor(...)`, never by hand. `App.tsx` switches on the route.
- **i18n** (`src/i18n/`): initialised by a side-effect import in `main.tsx`. Detection order is a saved choice in localStorage (`garden-designer.language`), then the browser language; `nl-*` maps to `nl`. On language change it updates `<html lang>` and `document.title`. Keys are type-checked against `locales/en.json` (`i18next.d.ts`). `locales.test.ts` enforces identical keys and `{{placeholders}}` in `en.json` and `nl.json`. Language names are endonyms in both files.
- **No hard-coded UI text:** the local oxlint plugin `scripts/oxlint-plugin-i18n.js` (rule `garden-i18n/no-literal-jsx-text`) flags letters in JSX text, static strings in JSX children, and user-facing attributes (`title`, `alt`, `placeholder`, `aria-label`, …). It is off for tests. Don't switch back to `eslint-plugin-i18next`: under oxlint it silently does nothing.
- **Data model** (`src/model/`): the zod schemas in `schema.ts` are the single source of truth; TS types are inferred from them. Changing stored data shape means bumping `SCHEMA_VERSION` and adding a step to `MIGRATIONS` in `migrations.ts` (`MIGRATIONS[n]` upgrades n → n+1). Units are metres; timestamps are epoch ms. Version 2 (M4) gave the background (site plan) its pixel size and calibration; its visibility/lock is the "background" layer. Version 3 (M5): plant colours come from a fixed palette (`PLANT_COLORS`, with flower/foliage/autumn subsets; hex values in `styles/plantColors.ts`) and `flowerColors` is a list (the first one is drawn). Version 4 (M6): `settings.overlapThreshold` (fraction of the smaller plant's diameter, default 0.2).
- **Persistence** (`src/persistence/`): Dexie/IndexedDB with tables `projects` and `assets` (binary files as `ArrayBuffer`, kept out of the project record). Always read projects through `loadProject()`, which migrates and validates. `.garden.json` export/import lives in `gardenFile.ts`: an import always creates a new project (new project and asset ids), and failures surface as `ImportError` codes that map to i18n messages. The project list reads via `useLiveQuery`, so it updates by itself after writes. Assets no longer referenced (a replaced or removed site plan) are kept while the design is open, so undo can bring them back; `pruneUnusedAssets` deletes them when a design is opened, and exports only include assets in use (`assetIdsInUse`).
- **Plant library:**
  - **Built-in plants** are JSON in `src/data/plants/<batch>.json`, merged by `index.ts` (`BUILT_IN_PLANTS`, `builtInPlant(id)`). The JSON is the source of truth, validated by `plants.test.ts` (schema, ranges, consistency), not at runtime. Ids are slugs of the Latin name, plus a suffix for a variant (`acer-campestre-hedge`). `verified: false` shows an "Unverified" badge; after the user spot-checks the tables from `npm run plants:review`, apply their corrections and set `verified: true`.
  - **Custom plants** are in `project.customPlants` with ids `custom-<uuid>`. `findPlant` looks there first, then in the built-ins; always display names through `plantName` (falls back to the other language, then Latin). Ops are in `model/plants.ts`; deleting a custom plant also removes its plantings (one undo step). `soilSuitability` is the soil rule for both the detail card and (M6) the warnings.
  - **UI** (`src/features/library/`): `LibraryPanel` (search, category tabs, filters; list ↔ `PlantDetail`), `PlantFormDialog` (custom plants), commands in `actions.ts`. Library view state is in `libraryStore`, not in `uiStore`. Search/filter logic is pure (`search.ts`: accent-insensitive, every word must occur in a NL/EN/Latin name); the form's draft ↔ plant conversion is in `plantForm.ts`.
  - **Symbols:** `styles/plantSymbols.ts` gives each category a symbol as SVG paths in a unit circle (radius = half the spread). The library draws them as SVG; the plan draws them as `Path2D` in Konva `sceneFunc`s (see Canvas). Months display through `i18n/months.ts` (`formatMonths` → "Jun–Aug"; runs continue over the turn of the year).
- **Beds & plantings** (M6):
  - **Beds** (`model/beds.ts`) are `GardenObject`s of kind `bed-ornamental` (layer "plants") or `bed-vegetable` (layer "vegetables") with a polygon shape. A planting's `bedId` is derived from geometry: `relinkBeds` links each planting to the topmost bed containing it, and every op that moves plants or changes beds calls it (`moveItems`, `transformObjects`, `pasteItems`, `deleteItems`, bed corner ops, `addPlantings`). Moving a bed takes its plants along (`withPlantsInBeds`); deleting a bed keeps its plants.
  - **Plantings** (`model/plantings.ts`): `addPlantings` (one undo step), `swapSpecies`, `speciesCodes` (1, 2, … in order of first appearance: language-independent label codes, also used by the planting list), `fillBedPositions` (staggered pattern from `geometry/planting.ts` minus spots overlapping existing plants; refuses > `MAX_FILL_PLANTS`), `defaultRowSpacingM` (hedge 0.33 m, crops their in-row spacing, else the spread). `plantingList.ts` counts per species, total or per bed.
  - **Warnings** (`model/warnings.ts`) are computed, never stored: `plantingWarnings(project, { view, radiusM })` gives overlap (sweep along x; hedging plants may overlap each other), outside-plot and soil (`soilSuitability`) warnings; `designWarnings(project, view)` caches per project version and growth view. Overlaps are checked at the size in the viewed growth year (default `'mature'`), between plantings already in the ground then; the plan, warnings list and properties all pass the view bar's year. Severity: soil `dry` is a `notice` (amber ring), the rest `warning` (red badge). Later kinds (sun, M12) plug in here.
  - **Look:** `styles/plantAppearance.ts` is the one place that sizes and colours a plant: `plantAppearance(plant, view, plantedYear)` with a `PlantView` `{ year, month }` (M13/M14, see View bar). Results are cached, so equal inputs give the same object. Season states map to colours there: flowering/leaf/autumn recolour the whole symbol; `bare` keeps only outlines (twig brown, `SEASON_COLORS`) plus the trunk; `dormant` is faint greys; a planting not in the ground yet in the viewed year is a `ghost` (see-through at its planting size, dashed ring, still selectable; `plantDrawing.ts` draws it). `styles/elementStyles.ts` has bed fills/outlines, the vegetable bed's row `pattern` and `PLANTING_MARKS` (selection, warning/notice colours, label font).
- **Design state** (`src/store/projectStore.ts`): a zustand store holding the open project plus its undo history (`past`/`future`). Every edit goes through `update(change, { history?, coalesce? })`. It bumps `updatedAt`, records an undo step, and autosaves after `AUTOSAVE_DELAY_MS` (debounced).
  - Updates sharing a `coalesce` key within 1 s merge into one undo step: text fields, nudges.
  - `history: false` keeps view-ish changes (layer show/lock) out of undo, and undo keeps the current layer state.
  - Commit continuous gestures (drags, transforms) once, on release.
  - `open`/`close` flush pending saves and use a generation counter, so overlapping calls (React StrictMode's double effects) can't clobber each other.
- **Editor** (`src/features/editor/`):
  - **View state** (viewport, selection, tool, cursor, help, label mode, stamp/fill state, dialogs) is in `src/store/uiStore.ts` and never in the project store. Tools: `select`, `pan`, `draw` (with a `DrawTarget`: plot, bed or row), `calibrate`, `stamp`, `fill`; starting one clears the others' state.
  - **Commands** (`actions.ts` → `editorActions`) are shared by the toolbar, panels and shortcuts. They read stores via `getState()` and prune the selection to editable items after undo/delete/locking.
  - **Shortcuts:** `shortcuts.ts` `SHORTCUTS` is the single source for key handling and the help dialog. Shortcuts are ignored while typing in form fields.
  - **Canvas:** the Konva canvas (`canvas/GardenCanvas.tsx`) is lazy-loaded. Its world group is transformed by the viewport (`screen = world × scale + offset`; metres in, pixels out).
    - Each item is a group at (0, 0). A drag or Transformer rotate/resize is baked into the item's coordinates on release via the pure ops in `src/model/edit.ts`, then the group is reset.
    - Copy Konva's `getTransform().getMatrix()` before resetting a node: it is reused and mutated in place.
    - Use `strokeScaleEnabled={false}` for pixel-width strokes.
    - Closed shapes that should only be clickable on their line need `fillEnabled={false}`: Konva hits the inside of a closed line even without a fill.
    - Draggable handles must have stable keys and props that don't change during their own drag (render them from committed data, show drafts elsewhere). A key change remounts the node and silently ends the drag.
    - Screen-space overlays (labels, handles, drawing preview) live in a separate layer and convert with `worldToScreen`.
    - Beds and plants are custom Konva `Shape`s whose `sceneFunc` draws with the native context (`canvas/plantDrawing.ts`) and reads the zoom at draw time (`getAbsoluteScale`), so pixel-sized things (outlines, labels, badges, less detail below 7 px radius) never need a React re-render on zoom; `Items` stays memoised. `hitFunc` draws a simple circle/polygon. Labels and warning badges of all plants are one shape on top (`PlantMarks`), following dragged groups via `handlers.offset`. Placement previews are one see-through shape (`PlantPreview`).
    - Beds get corner handles like the plot (`OutlineOverlay`, shared with `PlotOverlay`) instead of the Transformer.
    - Dropping a plant from the library is HTML drag and drop (`library/drag.ts`, `PLANT_DRAG_TYPE`): the drop target can't read the data during `dragover`, so the dragged id is also in `libraryStore.dragging`.
  - **View bar** (`view/`, above the plan, M13/M14): a year slider (`growthStops`: planting year … +10, fully grown; default fully grown), a month select with previous/next buttons (default "No month" = the usual colours) and the bloom chart button; the right-hand side is free for M11's sun date/time. State: `uiStore.growthStop`, `month`, `bloomChartOpen` (not undone, not saved, reset when a design opens). `view/plantView.ts` turns it into a `PlantView`: `usePlantView(project)` (stable object), `currentPlantView(project)` outside React, `growthViewOf` (stops count from `growthReferenceYear`, the earliest planting year). Anything else sized by the year uses the same view, e.g. tree shadows: `plantedSizeAt(plant, planting.plantedYear, view.year)` (null: not planted yet). `BloomChartDialog`: a 12-column table (`bloomChart`), whole design or one bed, a summary row of colour bands, hatched empty months with a hint; a month's column header shows that month on the plan.
  - **Side panels:** right: Properties, Warnings and Planting list (`CollapsibleSection`), Layers. The design settings dialog (toolbar gear, `SettingsDialog`) saves name, soil, grid size and overlap threshold as one undo step. Toolbar: one row that never wraps as a whole (the name field shrinks, then the tool groups wrap inside their box), so the plan's position doesn't jump when the save status changes length.
  - **Plot:** the plot is selectable as `PLOT_ID` and belongs to the "existing" layer. Its operations are in `src/model/plot.ts`; corners are labelled A, B, C, …
  - **Drawing tool** (`tool: 'draw'`, `uiStore.drawing` = target + points; plot outline, bed, or a row of plants along an open line): commands are in `editorActions` (`addDrawingPoint`, `addDrawingSegment`, `finishDrawing`, …). `DrawingPanel` sits below the plan and keeps the focus in its length field. Snapping (`src/geometry/snap.ts`, targets from `canvas/snapTargets.ts`) works in screen-pixel tolerances; Alt disables it. Grid snapping is a toggle (`uiStore.snapToGrid`, toolbar/`G`): off when a design with a visible site plan opens and after importing one, so traced corners land where you click.
  - **Site plan** (`project.background`, model ops in `src/model/background.ts`, maths in `src/geometry/calibration.ts`): selectable as `BACKGROUND_ID`, always on its own; shown/locked via the "background" layer. Pixels map to metres as `offset + R(rotationDeg)·(pixel × metresPerPixel)`; stored rotations are clockwise on screen (like Konva), the panel shows them map-style (anticlockwise positive). It's drawn by `canvas/SitePlan.tsx` in its own Konva layer (dragged and rotated with a Transformer, never resized).
    - **Import** (`siteplan/SitePlanImport.tsx`): owns the hidden file input; `editorActions.importSitePlan()` opens it via `siteplan/picker.ts` (must run inside the click handler). Images are stored as they are; a PDF page is rendered to PNG by `siteplan/pdf.ts` (lazy-loaded pdf.js, page chooser for multi-page PDFs, size capped by `pdfRenderScale`). pdf.js's worker is bundled via `?url`; its fonts, wasm decoders and ICC profiles are served from `<base>pdfjs/` by `scripts/vite-plugin-pdfjs-assets.ts` (dev and build), never from a CDN.
    - **Calibration** (`tool: 'calibrate'`, `uiStore.calibration`): two clicks (world points, not snapped) and a distance in `CalibrationPanel`; `applyCalibration` converts them to image pixels and keeps the line's midpoint in place. The line is stored in image pixels, so it follows the image.
  - **Zoom to fit** (`zoomTo` in actions): records `uiStore.fit`. While the viewport is still the fitted one, `GardenCanvas` re-fits when the plan area changes size (a panel below it opening/closing, a window resize), measuring the container in a layout effect. A click on the plan, pan or zoom ends that. `zoomToFit` uses the site plan's bounds only when the design has nothing else.
  - **Pure maths** is in `src/geometry/` (viewport, grid, bounds, transform, polygon, snap, calibration). Angles are map-style (0° right, 90° up) although y points down. Number display and parsing go through `src/i18n/units.ts` (decimal comma in NL, NBSP before units).
- **Time & print logic** (pure and unit-tested, for M13–M16; the UI calls it, nothing is stored; growth and season are wired up via the View bar):
  - **Growth** (`model/growth.ts`): `plantSizeAt(plant, plantedYear, view)`, where `view` is a year or `'mature'`. A plant starts at its category's planting size (`PLANTING_SIZE_BY_CATEGORY`; fruit trees, ≥ 3 m, get their own) and is never more than half its mature size at planting. It grows linearly to its mature size over `yearsToMature`; with `yearsToMature` ≤ 1 it is mature from the planting year. Before the planting year it has its planting size: check `isPlanted` to hide or ghost it. Slider stops come from `growthStops(growthReferenceYear(...))`.
  - **Season** (`model/season.ts`): `plantAppearance(plant, month)` returns `{ state, color }`; map `color` with `PLANT_COLOR_HEX`. The rule follows from `seasonalHabit`:
    - In bloom, the first flower colour always wins.
    - Autumn colour shows in Oct–Nov, for evergreens too.
    - Deciduous woody plants are `bare` (outlined) Dec–Mar. Herbaceous plants are `dormant` then, and deciduous grasses stay in their autumn colour until March.
    - Bulbs are in leaf from one month before they bloom to one month after. Annual vegetables and herbs show only while they are in the ground (`inGroundMonths`).
  - **Summaries** (`model/bloomChart.ts` → `bloomChart`, `model/vegCalendar.ts` → `vegCalendar`): per month, for the whole design or one `bedId`. Names come from `plantName`, plantings of unknown plants are skipped, and the sort order is stable.
  - **Rows** (`geometry/rows.ts`): `layoutRows(outline, { angleDeg, rowSpacingM, inRowSpacingM })` gives row pieces with plant positions. Each plant's row × in-row rectangle stays inside the bed (which may be concave), and a row splits where it crosses a notch. `defaultRowAngle` runs the rows along the longest edge.
  - **Print scale** (`export/scale.ts`): A4/A3 page layout (10 mm margin, 15 mm title block at the bottom) and `planAreaM`. `fitsAtScale` drives the warning; `bestScale` picks from 1:50/100/200 and `bestOrientation` suggests the orientation. `printedWorldBounds` is the world area the page shows, `planImageSizePx` and `pxPerMetre` are at 300 dpi, and `scaleBar` gives a 1/2/5 × 10ⁿ m length.
- **Sun & shade core** (M11/M12, pure, no UI yet):
  - **`geometry/sun.ts`** wraps suncalc **v2**: degrees, azimuth = compass bearing clockwise from north, apparent altitude (v1 used radians from south). Dates are `LocalDate` + minutes after local midnight in Europe/Amsterdam; `localInstant` handles DST via `Intl`, independent of the machine's zone. `northAngleDeg` = clockwise angle on screen from "up" to north, so bearing b lies along `(sin(north+b), −cos(north+b))` on the plan. `shadowStep(sun, north)` is the plan offset per metre of height (length 1/tan(altitude), altitude clamped to ≥ 1°), or null when the sun is down.
  - **`geometry/shadows.ts`**: casters are `prism` (a `MultiPolygon` footprint from `baseM` to `heightM`) or `canopy` (a disc from `baseM` to `topM`; trees start at ⅓ of their height). Polygons use polygon-clipping's `[x, y]` format with open rings. `shadowPieces` (no clipping, used per sample) → `mergePieces`/`shadowAt` (union for drawing; `toSvgPath` for a Konva `Path`). Polylines are buffered with round ends and joins, like the canvas draws them. No sun → no shadows.
  - **`geometry/projectCasters.ts`** turns a `Project` into casters (objects with `heightM`; trees, shrubs, hedging and fruit ≥ 0.5 m; pergolas/carports as roofs; `plantSize` option for growth). It's a separate file so the worker doesn't bundle the plant library.
  - **`geometry/sunHours.ts`**: a grid (0.5 m cells, row-major, `gridForBounds` caps the cell count), 15-min samples from sunrise to sunset, shadow pieces scan-converted per sample. `sunHoursJob` is a generator (one sample per step); `computeSunHours` (sync) and `computeSunHoursAsync` (time-sliced) take `onProgress` and an `AbortSignal`. Classification (`classifySunHours`, default 6 h / 3 h) maps to the `SUN_LEVELS` ids; `dominantSunLevel` + `sunMismatch` drive the plant warning.
  - **Worker** (`src/workers/`): `sunHoursClient.ts` (`createSunHoursClient().compute(input, { onProgress, signal })`) talks to `sunHours.worker.ts` using the messages in `sunHoursProtocol.ts`. The message logic is the plain `createSunHoursHandler` (unit-tested without a Worker), and the result's `hours` buffer is transferred. Build the casters on the main thread and pass them in.
- **Tests:**
  - **Setup:** `src/test/setup.ts` loads `fake-indexeddb/auto` first, then resets IndexedDB, localStorage, the URL hash and the language (`en`) before each test. `src/test/fixtures.ts` has a sample project/asset/plant.
  - **Fake timers:** fake only `setTimeout`/`clearTimeout`/`Date`, never `setImmediate`: fake-indexeddb runs on it.
  - **Canvas in jsdom:** jsdom has no canvas, so component tests that render the editor `vi.mock` the `GardenCanvas` module. The canvas is covered by Playwright.
  - **Locations:** Vitest only picks up `src/**/*.test.{ts,tsx}`. E2E specs live in `tests/e2e/`; each test gets a fresh browser context, so a fresh IndexedDB.
  - **e2e fixture:** the editor e2e tests import `tests/e2e/fixtures/sample.garden.json` and compute screen positions from the zoom-to-fit maths (padding 48 px), using the `plan-area` element's box *after* any panel below the plan has opened (a fitted view re-fits then), floored like the app's `elementSize`. Text with units contains NBSP, so regexes need `\s`.
  - **Plan size:** measure elements whose size feeds the maths with `elementSize` (`Math.floor` of `getBoundingClientRect()`), never `clientWidth`/`clientHeight`: those round, so a fractional height (font metrics differ on CI) put the app 1 px off the tests.
  - **Site plan e2e:** `siteplan.spec.ts` draws its test PNG in the page and builds a tiny PDF in code (no binary fixtures), reads the saved design straight from IndexedDB to map image pixels to the screen, and checks that importing makes no requests outside the app (its origin comes from `baseURL`, so `E2E_PORT` works).
  - **Planting e2e:** `planting.spec.ts` draws a bed by typed lengths, then drags (list and detail card), stamps, fills and plants a row, and checks the planting list; library drags use Playwright's `dragTo`.
  - **Seasons e2e:** `seasons.spec.ts` checks what the plan draws by reading pixels (`pixelAt` composites all canvas layers of the plan area over white) and classifying them (green leaves, blue flowers, brown trunk, pale), polling until Konva has redrawn.
  - **Konva hit map:** it refreshes on the next animation frame, so a click immediately after a state change can miss. Retry with `expect.poll`.
- **PWA / offline** (config in `scripts/vite-pwa.ts`, app side in `src/pwa/`):
  - **Service worker:** `vite-plugin-pwa` (`generateSW`, Workbox) builds `sw.js` and `manifest.webmanifest` in `vite build` only; it is disabled in dev and Vitest. It precaches every built file whose extension is in `PRECACHE_EXTENSIONS` (JS chunks incl. lazy ones, CSS, the pdf.js worker `.mjs`, the `pdfjs/` fonts/wasm/ICC files, icons): new chunks and assets are included automatically, but a new file *type* must be added to that list. A file over `maximumFileSizeToCacheInBytes` (4 MiB) fails the build. Navigation falls back to `index.html`; no runtime caching, no external requests.
  - **Updates:** the app registers the worker itself (`registerServiceWorker` in `main.tsx`, after `load`, production only) and checks hourly. A new version waits (`registerType: 'prompt'`, `clientsClaim` but no `skipWaiting`); `UpdatePrompt` (`role="status"`, only rendered while an update waits) offers Reload, which flushes the autosave, posts `SKIP_WAITING` and reloads on `controllerchange`.
  - **Icons:** `npm run icons` renders `public/icons/*.png` (192/512, maskable, apple-touch) from the favicon's leaf with Playwright's Chromium; the manifest colours are read from the `global.css` tokens. iOS meta tags are in `index.html`.
  - **Testing:** `tests/e2e/offline.spec.ts` waits for `navigator.serviceWorker.ready` + a controller, compares the precache with the files in `dist/`, then `context.setOffline(true)`, reloads and uses the app (responses must come from the service worker). It simulates a new version by registering `sw.js?next`. Other specs run with the worker installing in the background; in a page it controls, `page.route` doesn't see the requests it answers. To try offline by hand: `npm run build && npm run preview`, open the app once, then tick *Offline* in DevTools → Application → Service workers and reload.
- **Deploy:** `.github/workflows/ci.yml` runs verify (lint/typecheck/unit/build) and e2e on every push; on `main` a deploy job publishes `dist/` to GitHub Pages (https://xaveervanderlaan.github.io/garden.designer/). Vite `base` is `/garden.designer/`, so runtime asset URLs must use `import.meta.env.BASE_URL`, not `/`.

## Constraints from the spec

- Privacy and offline: no backend, accounts, analytics or external API/CDN calls. Bundle everything locally (as with pdf.js and its assets). User data stays in the browser (IndexedDB) and moves between devices only via exported `.garden.json` files.
- 2D top-down plan only; metres everywhere in the data model; NL uses a decimal comma, so number inputs must accept both `12,5` and `12.5`.
- Formatting: Prettier with no semicolons, single quotes, width 100; Markdown files are excluded from Prettier.
